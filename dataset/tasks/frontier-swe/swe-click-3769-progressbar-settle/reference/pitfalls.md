# 常见错误

1. **在显示层钳制数字**：把最终显示的 pos 直接写成 length 会让显示与内部状态脱节，且无法通过检查结算过程的参数化测试。
2. **破坏节流语义**：把 `make_step` 的节流逻辑删掉（每次都渲染）会引入显著的性能与输出回归，`PASS_TO_PASS` 中与渲染次数相关的用例会失败。
3. **在错误的位置结算**：余量必须在收尾输出（`AFTER_BAR` 等）之前结算，且结算后要重新渲染一次；只在 `__exit__` 里改计数而不触发渲染不会更新显示。
4. **忽略 hidden / 非 tty 分支**：修复应先结算余量，再保留原有的提前返回逻辑；顺序颠倒会改变无终端场景的行为。
